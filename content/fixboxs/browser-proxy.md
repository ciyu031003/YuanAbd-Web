# 浏览器打不开网页但其他应用正常？浏览器代理与 PAC 设置修复

> ⚠ 需谨慎：清除代理会让浏览器恢复直连；公司、学校或 VPN 环境可能依赖统一代理，执行前先确认配置来源。

> ℹ️ 本教程只动浏览器和系统代理设置，全部可逆，不涉及数据删除。唯一的坑是改设置前没截图——改乱了照着截图改回来即可。

## 合规提示

浏览器代理设置本身没有合规问题；但如果你是在**公司或学校网络**里排查，代理很可能是 IT 统一下发的管控配置——按本文「截图留底、改回原样」的原则操作，不要用它来绕过单位的访问审计。

## 一句话结论

「微信能用、浏览器不能用」说明网络是通的，**锅在浏览器的代理路径上**：要么系统代理指向了一个已经死掉的代理端口，要么某个代理插件接管了请求。把浏览器代理改回「使用系统代理设置」或「不使用代理」，九成当场恢复。

## 30 秒快速排查

1. 换一个浏览器（Chrome ↔ Edge ↔ Firefox）开同一个网页。**期望结果**：另一个浏览器能开 → 锅在第一个浏览器的插件/独立代理配置，直接去它的插件管理页把代理插件关掉。
2. 记住报错关键词：`ERR_PROXY_CONNECTION_FAILED` / `ERR_TUNNEL_CONNECTION_FAILED` → 实锤代理问题，走本文；`DNS_PROBE_FINISHED_NXDOMAIN` → 是 DNS 问题，看[「网页打不开但 QQ / 微信能用：DNS 问题怎么修」](./dns-broken-but-app-works.html)。
3. 回忆最近装过的浏览器插件（尤其是 SwitchyOmega、各类加速/翻译/安全插件），先全部禁用再逐个放开。**期望结果**：禁用某个插件后恢复，锁定元凶。

## 小白一键修复

- 下载：[清除异常代理设置（.bat）](../scripts/reset-proxy-settings.bat)
- 适合：Windows 10/11，只有浏览器打不开网页，QQ/微信正常，且最近安装或卸载过代理、VPN、抓包工具。
- 脚本会：关闭当前用户的系统代理和 PAC，重置 WinHTTP 代理，并清理 DNS 缓存。
- 运行前：记下公司或 VPN 的代理地址；企业设备、公司内网电脑不要自行运行。
- 注意：脚本会移除原有代理配置，不会删除浏览器扩展；关闭后需要恢复内网代理时请联系 IT。

## 适用 / 不适用

**适用**

- 浏览器报 PROXY/TUNNEL 相关错误码。
- 用过抓包工具、加速器、代理插件之后浏览器就不通了。
- 系统代理被改过（比如退出某软件后没还原）。

**不适用**

- 所有应用都上不了网 → 是网络层问题，看[「Wi-Fi 有信号但上不了网」](./wifi-connected-but-no-internet.html)。
- 公司电脑受管控：代理由 IT 统一下发，改回去会自动恢复成公司的配置，看[「公司电脑上不了网 / 提示证书不受信任？企业代理环境排查」](./enterprise-proxy.html)。
- 网页能开但部分站点特别慢 → 更接近 DNS/线路问题，不是代理。

## 开始前确认

- [ ] 微信/QQ 能正常收发消息（确认前提症状成立）。
- [ ] 截图当前浏览器的代理/插件状态。
- [ ] 知道自己是否需要某个代理工具正常工作（需要的记下它的正确端口）。

## 分步骤

### 步骤 1：把浏览器代理改回「跟随系统」

![Chrome 设置里的「计算机的代理设置」入口](../img/guides/chrome-proxy-entry.webp)
Chrome / Edge 里打开「设置 → 系统 → 计算机的代理设置」，点了会直接跳到 Windows 的系统代理页。

1. Chrome/Edge：设置 → 搜索「代理」→ 打开「计算机的代理设置」（会跳系统设置）。确认浏览器没有独立的代理覆盖——Chromium 系默认跟随系统。
2. Firefox：设置 → 最底部「网络设置」→ 选「使用系统代理设置」或「不使用代理」（自建代理用户选后者）。
3. 保存后重启浏览器。
**期望结果**：网页恢复。**失败了怎么办**：仍报错 → 步骤 2 查系统代理本身。

### 步骤 2：检查系统代理（浏览器跟随的就是它）

![Windows 设置 → 网络和 Internet → 代理：手动代理被打开的样子](../img/guides/win11-proxy-on.webp)
如果「使用代理服务器」这个开关是蓝色，说明代理正在生效——点一下让它变灰，再点「保存」。这就是「浏览器打不开网页、微信却正常」最常见的原因。

![三个开关都变灰才是干净状态](../img/guides/win11-proxy-off.webp)
「自动检测设置」「使用设置脚本」「使用代理服务器」三个开关全部为灰，才说明系统层没有代理在拦。

1. Windows：设置 → 网络和 Internet → 代理。**「自动检测设置」关掉、「使用设置脚本」关掉、「手动代理」关掉**（自建代理用户除外，按自己的端口填）。
2. macOS：系统设置 → 网络 → 详细信息 → 代理：把所有勾选清空（自建除外）。
3. 命令行复核（Windows）：`netsh winhttp show proxy`，显示「直接访问」为干净状态。
**期望结果**：系统代理清空后浏览器恢复。**失败了怎么办**：关了又被自动改回去 → 有软件在抢代理，看[「装了代理工具后网络乱了怎么办」](./proxy-tool-broke-network.html)。

### 步骤 3：清理代理类插件

1. 打开浏览器扩展管理页（地址栏输入 `chrome://extensions` 或 Edge `edge://extensions`）。
2. 禁用所有代理/加速/抓包相关插件（SwitchyOmega、各类「安全上网」插件）。
3. 逐个重新启用，每启用一个就开一个网页验证，锁定并卸载出问题的那个。
**期望结果**：定位到元凶插件并恢复正常。**失败了怎么办**：全部禁用仍不通 → 回步骤 1/2 确认系统层干净。

### 步骤 4：PAC 脚本报错的专项处理

1. 系统代理里若填了 PAC/脚本地址而脚本服务器已失效 → 关掉「使用设置脚本」。
2. 自建代理用户：确认 PAC 文件里的代理 IP:端口与实际监听一致，浏览器访问 PAC 地址能看到脚本内容。
3. 公司电脑的 PAC 由 IT 下发，别乱关：看[「公司电脑上不了网？企业代理环境排查」](./enterprise-proxy.html)。
**期望结果**：PAC 修复或安全关闭。**失败了怎么办**：需要 PAC 但总报错 → 换固定代理地址直填测试，二选一。

### 步骤 5：重置浏览器网络相关配置（兜底）

1. Chrome/Edge：设置 → 重置设置 →「将设置还原为原始默认设置」（不清书签和密码，但会禁用插件、清启动页）。
2. Firefox：帮助 → 更多故障排除信息 →「刷新 Firefox」。
3. 重置后再按步骤 1 核对一遍代理。
**期望结果**：浏览器回到干净状态且可正常上网。**失败了怎么办**：重置后仍不通 → 新建一个系统用户测试，能上则原用户配置有残留，继续排查或迁移配置。

## 怎么确认修好了

- 常用网站全部秒开，无 PROXY/TUNNEL 报错。
- 重启浏览器与电脑后依旧正常。
- 插件列表里没有来路不明的代理插件。

## 还是不行？

- 代理被反复自动改写 → 有后台进程在改，卸载对应软件（任务计划/启动项里找）。
- 只有某个特定网站打不开、其他都好 → 是站点或 DNS 问题，不是代理。
- 系统重置也无解 → 新建 Windows 用户验证，仍异常再考虑重装；数据先备份。

## 预防

- 代理类工具用完即退出，别让它常驻改系统代理。
- 浏览器插件只装必要的，代理插件能不装就不装（系统层配置一次即可）。
- 改代理前截图，10 秒钟换来的后悔药。
