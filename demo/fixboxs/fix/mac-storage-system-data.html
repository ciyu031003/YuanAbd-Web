Mac 储存空间不足 /「系统数据」占了上百 G

macOS 12+进阶30-90 分钟⚠ 需谨慎

⛔
⛔ 有数据风险：本文会删除缓存、日志、本地快照和备份文件。动手前请先把重要文件复制到外置硬盘或云盘，并确认你删除的每一项都不是唯一副本。

💡 一句话结论

「系统数据」不是病毒也不是系统垃圾，它大多是缓存、日志、时间机器本地快照和 iPhone 备份。先删本地快照和缓存，再按体积找大文件，动手前一定先备份。

⚡ 30 秒快速排查（先试这个）

  1. 打开系统设置 → 通用 → 储存空间，等进度条算完，看「系统数据」旁边写了多少。期望：拿到一个具体数字（例如 120 GB）。
  2. 在终端执行 tmutil listlocalsnapshots /。期望：如果出现一排 com.apple.TimeMachine.2026-... 记录，说明本地快照正在占空间，通常是几十 GB。
  3. 打开访达，按住 Option 点菜单栏「前往」→「资源库」，进入 Caches 文件夹，按大小排序看前几名。期望：能看到几个明显很大的缓存文件夹。

适用 / 不适用

适用：

  • 系统设置里「系统数据」几十到几百 GB，可用空间越来越少
  • 提示「启动磁盘几乎已满」「储存空间不足」
  • 删了文件、清了废纸篓，可用空间却没怎么变
  • 想找出到底是哪些文件在占空间

不适用（请转对应文章）：

  • iCloud 云盘、iCloud 照片提示空间不足 → iCloud 储存空间不足怎么办
  • 磁盘工具报错、SMART 状态异常、磁盘发出异响 → Mac 磁盘报错与磁盘工具急救
  • 系统已经卡到进不去桌面 → Mac 无法开机 / 反复重启怎么办
  • 准备抹掉磁盘重装系统 → 先看 Mac 重装系统前如何完整备份

开始前确认

  • 重要文件已复制到外置硬盘、NAS 或云盘，并实际打开确认能打开
  • Mac 已接电源
  • 知道管理员密码（下面多条命令需要 sudo）
  • 记下当前「可用空间」的数字，方便清理后对比
  • 本文删除的内容无法从废纸篓恢复（快照、缓存、备份都是直接删除）

怎么确认修好了

同时满足两条：

  1. 系统设置 → 通用 → 储存空间 里，「系统数据」比清理前明显变小（多数情况能减少 20-80 GB），可用空间达到磁盘总容量的 15% 以上（512 GB 的盘至少留 75 GB）；
  2. 在桌面新建一个 1 GB 的大文件、复制到别处再删除，全程不提示「储存空间不足」，Finder 删除文件后可用空间会即时回升。

还是不行？

  • 清理后几天又涨回来 → 回到步骤 3、4 找持续写入的 App（同步盘、虚拟机、录屏软件、日志狂写的软件）
  • 大头是 iPhone 备份而你不打算从本机恢复 → 删掉 MobileSync/Backup 下对应的备份目录，注意删了就无法从本机恢复
  • 磁盘工具报错或 SMART 异常 → 先完整备份，再送修（Apple 授权服务商）
  • 磁盘本身太小，清理已到极限 → 外接 SSD 存放素材，或更换容量更大的机型；公司/学校设备联系 IT

预防

  1. 开启时间机器并接一块外置硬盘做完整备份，同时定期用 tmutil listlocalsnapshots / 检查本地快照数量。
  2. 每月花 5 分钟看一次「储存空间」，顺手清空下载文件夹和废纸篓。
  3. iPhone 备份改用 iCloud，或导出到电脑后立即删除本机备份。
  4. 不装「一键清理/加速」类第三方工具，不手动删除系统目录。
  5. Xcode、Docker、虚拟机用户每月清理一次 DerivedData、无用镜像和旧模拟器。

分步骤

  1. 先看清空间到底在哪

    目的：分清「真的被占满」和「系统把可随时回收的空间算成了占用」。

    操作：

    1. 系统设置 → 通用 → 储存空间，等分类算完，把每一类都点开看一遍。
    2. 终端执行：
    df -h /System/Volumes/Data
diskutil info / | grep -i -E "Free Space|可用空间"
    预期结果：能同时看到系统设置里的分类数值和命令行里的可用空间。两者略有差异是正常的：macOS 有一部分空间叫「可清除空间」，系统需要时会自动回收，所以不同界面显示可能不一致。

    按 Apple 的说法，「系统数据」收纳的是无法归入文稿、照片、邮件等类别的文件，常见包括：应用缓存、日志、时间机器本地快照、iPhone/iPad 本机备份、字体、插件和部分 App 支持文件。

    失败怎么办？
    储存空间界面长时间只显示「正在计算…」，先接上电源再等几分钟；df 看到的是数据宗卷，不要去看只读的系统宗卷，那是正常的系统占用。

  2. 删除时间机器本地快照

    ⛔
    ⛔ 有数据风险：本地快照是你最近一次可以回滚的时间点，删掉后就不能再用它恢复文件。如果这台 Mac 很久没做过完整备份，请先做一次外部备份。

    目的：本地快照是「系统数据」变成几十上百 GB 的头号原因。

    操作（终端，逐条执行）：

    # 1. 先看有哪些本地快照
tmutil listlocalsnapshots /

# 2. 删除全部本地快照（不会删你的文件）
sudo tmutil deletelocalsnapshots /

# 3.（可选）只瘦身、保留最近的快照，示例约释放 10GB 以上
sudo tmutil thinlocalsnapshots / 10000000000 4
    预期结果：第 1 条列出形如 com.apple.TimeMachine.2026-10-11-103000.local 的快照名；第 2 条逐个返回 Deleted local snapshot '...'；随后系统设置里的「系统数据」明显下降。
    失败怎么办？
    提示 Operation not permitted 或 No local snapshots，先执行 tmutil status 看是不是正在备份；等备份结束再试。仍然失败说明该宗卷没有可删的本地快照，直接进入步骤 3。

  3. 清理缓存与日志（安全范围）

    ⛔
    ⛔ 有数据风险：只删缓存和日志。不要删 ~/Library/Application Support、~/Library/Keychains、~/Library/Preferences、/Library/Extensions、/System，里面是应用数据、钥匙串和系统文件。

    目的：缓存和日志是可以安全重建的占用，删掉不影响功能。

    操作：

    1. 先量一下大小：
    du -sh ~/Library/Caches 2>/dev/null
sudo du -sh /Library/Caches 2>/dev/null
du -sh ~/Library/Logs 2>/dev/null
    1. 打开访达，按 Option 点「前往」→「资源库」，进入 Caches，按大小排序，删掉明显很大的那几项（例如浏览器、地图、视频软件的缓存）。
    2. Logs 里可以删掉旧的日志文件。
    3. 终端执行 sudo du -sh /Library/Logs 检查系统日志目录，体积大时可删旧的 .log 文件。
    预期结果：可用空间增加几个 GB 到几十 GB。
    失败怎么办？
    提示「不能删除，因为正在使用」→ 先退出对应 App 再删；删除缓存后第一次打开某个 App 会变慢，这是正常现象。任何你看不懂名字的文件夹，一律不要删。

  4. 用体积排行找出真正的大文件

    目的：把"猜"换成"看到"。

    操作（终端，逐条执行，输出可能较慢）：

    # 主目录下各文件夹体积，最大的在最后
du -sh ~/* 2>/dev/null | sort -h | tail -n 20

# 资源库下各文件夹体积
du -sh ~/Library/* 2>/dev/null | sort -h | tail -n 20

    常见的大户和正确处理方式：

    位置是什么怎么处理
    ~/Library/Application Support/MobileSync/BackupiPhone/iPad 本机备份在访达里删除不需要的备份；删了就无法从本机恢复该手机
    ~/Library/Developer/Xcode/DerivedDataXcode 编译中间产物可整个删除，Xcode 会重建
    ~/Library/Developer/CoreSimulatoriOS 模拟器可在终端执行 xcrun simctl delete unavailable
    ~/Library/Containers沙盒应用的数据不要手删，用应用自带的清理功能
    ~/Downloads下载文件夹自己看一眼，删掉已经不需要的安装包
    ~/Library/Mail / ~/Library/Messages/Attachments邮件附件、信息附件在对应 App 里删；邮件需清空「废纸篓」
    Docker / 虚拟机镜像容器与虚拟磁盘装了 Docker 可执行 docker system prune -a；虚拟机用自带工具压缩磁盘
    /private/var/vm交换文件与睡眠镜像不要手动删，重启后系统会自行回收
    预期结果：能明确说出是哪几个目录在占空间，并对可删的目录动手清理。
    失败怎么办？
    输出太长看不过来，把 tail -n 20 改成 tail -n 10；du 报权限错误属正常，忽略即可。

  5. 用系统自带功能收尾

    目的：图形界面里能一眼看懂的清理，交给系统。

    操作：

    1. 系统设置 → 通用 → 储存空间，逐个分类点开：删除不用的 App、删掉「文稿」里的大文件、清理「信息」里的附件、删除已下载的电影与剧集。
    2. 清空废纸篓（访达 → 废纸篓 → 清倒废纸篓）。放进废纸篓的文件仍然占空间。
    3. 照片：如果不使用 iCloud 照片，请在「照片」App 里自行删除不需要的照片与视频，并清空「最近删除」；如果使用 iCloud 照片，「优化 Mac 储存空间」才有意义。
    4. 删除 App：从「应用程序」拖到废纸篓，再用 App 自带的卸载器清理残留。
    5. 不要安装「一键清理 / 系统加速」类工具；系统自带的「储存空间」已经覆盖了主要场景。
    预期结果：系统设置里各类别的数值下降，可用空间回到 15% 以上。
    失败怎么办？
    删不动、提示权限不足 → 确认你删的是自己账户下的文件，系统目录不要碰；时间机器备份盘上的旧备份需要单独处理，且以 Apple 官方说明为准。

  6. 检查磁盘健康与"删不掉的空间"

    ⛔
    ⛔ 有数据风险：磁盘检查与修复过程中如果磁盘本身有故障，可能无法恢复。请确认重要文件已有外部副本再继续。

    目的：排除磁盘错误导致空间统计异常。

    操作：

    1. 先看磁盘结构：
    diskutil list
    1. 打开磁盘工具（访达 → 应用程序 → 实用工具），点「显示」→「显示所有设备」，选中启动磁盘下的「Macintosh HD - 数据」宗卷，点「急救」。
    2. 如果「系统数据」持续增长：重启进入安全模式再清理一次，观察是否还在涨。
    预期结果：急救显示宗卷似乎正常；清理后可用空间稳定不再掉。
    失败怎么办？
    急救报错、SMART 状态不是「已验证」，说明磁盘可能有硬件问题——先备份，再联系 Apple 支持或授权服务商。命令行的 diskutil 修复动词对 APFS 支持有限，请以「磁盘工具」的急救为准，并以 diskutil help 的输出和 Apple 官方文档为依据。
