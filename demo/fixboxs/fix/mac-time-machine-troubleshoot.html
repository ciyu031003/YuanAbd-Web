时间机器备份卡住 / 失败怎么修（含备份盘满了怎么办）

⚠ 需谨慎：备份盘出问题时不要随手格式化——里面有你的历史备份。Apple 官方的修复路径是「磁盘工具 → 急救」而不是重格；磁盘满了解决之道是换更大的盘，而不是删备份（时间机器自己会滚动清理最旧备份）。

💡 一句话结论

时间机器卡住/失败的四大惯犯按概率排：磁盘连接/格式问题、磁盘空间满、磁盘需要「急救」、首次备份本来就慢（几百 GB 走 USB 需要数小时到一晚，卡在「正在准备备份」几小时往往是正常的）。按 Apple 官方排查序：查连接 → 查空间 → 磁盘急救 → 重选备份盘，别动不动就重格。

⚡ 30 秒快速排查（先试这个）

  1. 看卡在哪个阶段：菜单栏时间机器图标 → 「正在准备备份」（可等，尤其首次）/「正在备份 X of Y」不动 1 小时+（异常）。期望结果：先分辨「慢」和「死」。
  2. 备份盘连接与格式：插入后在「磁盘工具」能看到吗？格式是 APFS 或 Mac OS 扩展（HFS+）吗（NTFS 盘不能当时间机器盘）？期望结果：盘可见且格式正确。
  3. 空间：备份盘容量 ≥ Mac 已用空间 × 2 最稳（Apple 官方建议备份盘至少与被备份数据一样大，2 倍能保住历史版本）。期望结果：空间充足。

适用 / 不适用

适用

  • 时间机器备份一直「准备中」不动、备份到一半失败。
  • 提示「备份磁盘已满」「找不到备份磁盘」「备份磁盘只读」。
  • 备份慢到怀疑人生。
  • 换了新备份盘想把旧备份迁走。

不适用

  • 还没配过时间机器、想从零开始：看「换硬盘 / 重装系统前，怎么把数据备份全」步骤 3 的配置流程。
  • Mac 本体存储不足（「系统数据」几百 G）：看「Mac 储存空间不足 /「系统数据」占了上百 G」。
  • 备份盘在电脑上完全不识别（磁盘工具都看不到）：硬件问题，参考「U 盘 / 移动硬盘不识别、提示格式化怎么办」。

开始前确认

  • 确认当前阶段（准备中 / 备份中失败 / 磁盘满提示）。
  • 备份盘容量与 Mac 已用容量心里有数。
  • 记下备份盘名字（多块盘时别选错）。
  • 有急事要备份的，先手动把最要命的文件拷一份到别处——别把鸡蛋都押在排障上。

怎么确认修好了

  • 一次完整备份跑完，菜单栏显示「最新备份：今天 xx:xx」。
  • 之后每小时自动备份静默成功（看一眼时间机器设置里的进度记录）。
  • 随便进时间机器界面能浏览历史版本。

还是不行？

  • NAS 备份反复失败 → 回退到 USB 直连盘验证：直连好 = NAS 兼容/网络问题（NAS 固件更新、按「某些房间 WiFi 信号差」改善网络，NAS 最好有线）。
  • 备份慢得离谱（一晚只走几个 G）→ 换 USB 3.0+ 口与线；机械盘是瓶颈就接受或换 SSD 备份盘。
  • 换 Mac 后旧备份打不开 → 新 Mac 用「迁移助理」从备份恢复（比手动翻备份目录正确一万倍）。

预防

  • 备份盘容量 = 已用空间 ×2，一劳永逸远离「磁盘已满」。
  • 每季度做一次「恢复演练」：真从时间机器恢复一个小文件——没验证过的备份等于没有备份。
  • 备份盘专盘专用，不当日常拷贝盘（减少故障与误格式化风险）。

更新日志

  • 2026-10-25 v1.0：首版发布。排查顺序与「磁盘满/急救/重选盘」口径均参照 Apple 官方时间机器支持文档。

分步骤

  1. 连接与基础状态（Apple 官方排查第一步）

    1. 备份盘拔下重插；换一个 USB/雷雳口；换一根线（移动硬盘盒的桥接芯片也会闹脾气）。
    2. NAS 备份用户：确认 Mac 与 NAS 同网且 NAS 固件为最新（群晖/铁威马对时间机器的兼容修复很频繁）。
    3. 系统设置 → 通用 → 软件更新：macOS 装齐（官方排查表明确项）。

    期望结果：盘稳定可见。失败了怎么办：盘可见但仍报错 → 步骤 2。

  2. 磁盘工具「急救」

    1. 打开「磁盘工具」→ 显示所有设备 → 选中备份盘的卷（不是物理盘也顺手做一下）→ 「急救」→ 运行。
    2. 急救完成看报告：「操作成功」→ 回时间机器重新备份；「无法修复」→ 盘或分区表有损伤，按「格式化后 / 分区不见了，数据还能救回来吗」先抢救旧备份，再考虑换盘。

    期望结果：文件系统修复，备份恢复。失败了怎么办：急救好了还失败 → 步骤 3。

  3. 只读 / 权限问题

    1. 提示「备份磁盘只读」：磁盘工具选中该卷 → 卸载 → 重新挂载；仍只读说明卷有损坏或开了硬件写保护。
    2. 换盘测试：另一块盘设为时间机器盘，备份正常 → 原盘问题实锤；同样失败 → Mac 端问题（重选备份盘/重置时间机器配置）。
    3. 「重选」：系统设置 → 时间机器 → 删除旧盘 → 重新添加（会开始新备份链；旧备份仍在盘上可用）。

    期望结果：读写正常、备份链重建。失败了怎么办：进步骤 4。

  4. 磁盘已满的正确处理

    1. 首选：换更大的盘（Apple 官方建议：连接新备份盘并在设置里重新选定；容量按已用空间 ×2 买）。旧盘上的历史备份仍可手动挂载浏览。
    2. 让时间机器自己滚动清理：它默认会自动删除最旧的备份来腾空间——频繁报满是因为盘太小或每日变更量太大。
    3. 减少备份量：时间机器选项 → 排除大而不重要的目录（下载、虚拟机镜像、废纸篓），立竿见影。
    4. 不要手动进盘里删备份文件夹——会破坏备份链结构。

    期望结果：满的问题消失。失败了怎么办：换盘后仍报满提示 → 新盘分区/GPT 有问题，磁盘工具抹掉（APFS）后重选。

  5. 卡在「正在准备备份」几小时

    1. 首次备份/大更新后的准备阶段确实可能数小时（在构建快照与变更清单），插着电源过夜等一次。
    2. 反复卡同一进度：终端跑 tmutil status 看实际进度（比菜单栏图标诚实）；tmutil destinationinfo 确认目标盘。
    3. 顽固卡死（进阶）：停用再启用时间机器；或终端 tmutil stopbackup 后重来；仍不行用 sudo tmutil resetcatalog（重置备份目录索引，不影响备份数据本体）。

    期望结果：备份推进或重建后正常。失败了怎么办：始终无法推进 → 旧备份链已损坏，换新盘开新链（旧盘数据按恢复篇抢救）。
