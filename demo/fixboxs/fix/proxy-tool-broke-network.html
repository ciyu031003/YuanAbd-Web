装了抓包/加速工具后全网断网怎么恢复

📌 合规提示
本文只讲把被工具改乱的网络设置恢复原状（虚拟网卡、系统代理、DNS、路由表、Winsock 栈），属于本机故障排查。
本文不涉及任何跨境访问方法，不提供、不推荐任何用于绕过网络管理措施的软件或配置；抓包相关内容仅限在自有设备、自有网络上排查自己的网络问题。
请遵守《中华人民共和国网络安全法》及所在单位网络管理规定。设备由单位统一管理时，请先联系单位 IT，不要自行删除管控客户端。
⚠
⚠️ 本文会修改网卡、路由表与系统网络栈。改之前请把当前状态记录下来（ipconfig /all、route print 的输出各截一次图存好），以便对照还原。

💡 一句话结论

这类工具会装一块虚拟网卡（TAP/TUN/WinTun）并改写默认路由、DNS 和系统代理，卸载只删了程序、没删这些改动；按"卸软件 → 删虚拟网卡 → 清代理 → 修 DNS → 清路由表 → 重置网络栈"这个顺序来，绝大多数能救回。

⚡ 30 秒快速排查（先试这个）

  1. 右键任务栏网络图标 → "网络和 Internet 设置"，看适配器列表里是不是多了一块不认识、带黄色感叹号或"未识别的网络"的网卡（名字里常带 TAP、TUN、WireGuard、WinTun、VPN 字样）。期望结果：找到那块多余的虚拟网卡。
  2. 打开"设置 → 网络和 Internet → 代理"，把自动检测、脚本、手动代理都关掉，刷新网页。期望结果：网页能打开，说明只是代理残留。
  3. 命令行执行 ipconfig /all，看默认网关还在不在（正常应该指向你家路由器地址）。期望结果：默认网关为空或指向一个陌生地址，说明路由被工具接管了。

适用 / 不适用

适用

  • 装过抓包工具（Wireshark 及其抓包驱动）、游戏加速器、网络代理客户端之后，所有联网软件都上不了网。
  • 已经卸载了那个工具，网络仍然不通。
  • 能连上 Wi-Fi、能拿到 IP，但打不开任何网页、ping 公网也不通。

不适用

  • 只有浏览器报"代理服务器无响应"，其他软件正常：看「浏览器提示「代理服务器无响应」怎么修」。
  • 网卡在设备管理器里完全消失了：看「电脑没有 WLAN 选项 / 网络适配器不见了」。
  • 家里所有设备（含手机）都上不了网：不是本机问题，看「家里所有设备都上不了网：先分清是谁的问题」。
  • 公司/学校电脑上装了单位统一下发的管控或 VPN 客户端：请联系 IT，不要自行删除。

开始前确认

  • 确认这台设备是你本人的；单位设备先联系 IT。
  • 先记录当前状态：命令行执行 ipconfig /all 与 route print，把输出截图或存成文本文件。
  • 准备好联网的备用手段：手机 USB 共享网络或手机热点（万一网卡被删了还能下载驱动）。
  • 想清楚断网前装过哪些网络类软件，名字记下来，步骤 1 要用。
  • 关闭正在运行的下载、同步任务，避免重置过程中断在半路。

怎么确认修好了

重启电脑后不做任何手动设置，直接打开浏览器访问 3 个不同网站（至少一个视频网站）都能正常加载；同时 route print -4 里 0.0.0.0 默认路由只有一条、指向真实网卡；设备管理器里没有多余的 TAP/TUN 虚拟网卡。

还是不行？

  • 能上内网、上不了外网，或反过来 → 分流路由残留，个人设备按本文步骤 5-6 再做一遍；公司设备请联系 IT。
  • 网卡在设备管理器里彻底不见了 → 看「电脑没有 WLAN 选项 / 网络适配器不见了」。
  • 网线插上没反应、网口灯不亮 → 看「网线插上没反应 / 网口灯不亮怎么排查」。
  • 全部步骤做完仍不通 → 用手机热点连一次，如果热点下正常，说明是家庭网络侧问题，看「家里所有设备都上不了网：先分清是谁的问题」；热点下也不通就是本机系统问题，可考虑用系统还原点回退，或联系品牌售后/维修点处理——单位设备一律联系 IT。

预防

  1. 装这类工具前，先手动创建一次系统还原点，出事能一键回退。
  2. 卸载此类工具时，优先用它自带的"恢复网络设置/卸载驱动"选项，别只删程序目录。
  3. 不要在正在办公、开会的电脑上试用抓包或加速类工具；先用备用机或虚拟机。
  4. 卸载完成后按本文步骤 3-6 自查一遍，再重启确认。
  5. 公司电脑上不安装来源不明的网络工具，需要抓包时向 IT 申请测试环境。

分步骤

  1. 把工具本体彻底卸载

    目的：先拆掉"不断写设置"的源头，否则后面清完它又改回去。

    操作：

    1. 退出该软件的托盘进程（右下角图标右键 → 退出）。
    2. 打开"设置 → 应用 → 已安装的应用"，找到并卸载。
    3. 优先用该工具自带的卸载程序；如果它自带"恢复网络设置/清除驱动"的选项，先勾上。
    4. 卸载完重启电脑。
    ⛔
    ⛔ 不要为了"清干净"去删公司管控客户端或安全软件，那属于绕过管控，请联系 IT。
    预期结果：程序从应用列表消失，重启后托盘不再出现它的图标。
    失败怎么办？
    卸载程序报错或列表里找不到它，先在"任务管理器 → 服务/启动"里停掉相关项，再从该软件官方网站找卸载说明；仍无法卸载时做下一步（删虚拟网卡）也能恢复大部分网络。

  2. 删除残留的虚拟网卡（TAP / TUN / WinTun）

    目的：这块残留的虚拟网卡常常还是"默认路由"的出口，导致真实网卡的流量被送进一个已失效的隧道。

    操作：

    1. Win + X → 设备管理器 → 展开"网络适配器"。
    2. 逐条看设备名，见到 TAP-Windows Adapter V9、TAP-Windows6、TUN、Wintun、WireGuard Tunnel、OpenVPN、XXX VPN Adapter 这类名字，就是虚拟网卡。
    3. 右键该设备 → 卸载设备 → 勾选"删除此设备的驱动程序软件" → 卸载。
    4. 全部多余的虚拟网卡都这样删掉，然后重启。
    预期结果：设备管理器的"网络适配器"里只剩真实网卡（Intel/Realtek/MediaTek 这类无线或有线网卡）和系统自带项。
    失败怎么办？
    卸载后重启又自动出现，说明还有服务在重建它——回到步骤 1 再查一遍是否真的卸载干净；删错了真实网卡也没关系，重启后 Windows 一般会自动重装，或用"扫描检测硬件改动"重建。

  3. 清除系统代理与 WinHTTP 代理

    目的：工具常会把系统代理指向本机端口（如 127.0.0.1:某端口），程序关掉后这个端口已经没人监听，所有网页就都打不开。

    操作：按 Win + I → 网络和 Internet → 代理，关闭"自动检测设置""使用设置脚本""使用代理服务器"三项。

    再以管理员身份打开命令提示符，执行：

    netsh winhttp show proxy

    确认输出里没有残留的 127.0.0.1 或陌生地址后，若确实有，执行：

    netsh winhttp reset proxy

    macOS 上在"系统设置 → 网络 → 详细信息 → 代理"里关闭所有代理开关，或执行：

    scutil --proxy
sudo networksetup -setwebproxystate "Wi-Fi" off
sudo networksetup -setsecurewebproxystate "Wi-Fi" off
    预期结果：Windows 设置里的代理开关全是"关闭"；netsh winhttp show proxy 显示"直接访问"。
    失败怎么办？
    开关点不动，检查是不是被组策略或安全软件锁定；个人设备可临时退出安全软件再试，试完记得开回来。

  4. 恢复 DNS 设置

    目的：工具常把 DNS 改成自己的本机解析端口（如 127.0.0.1），程序没了，域名就再也解析不出来。

    操作：

    1. Win + R → ncpa.cpl → 右键当前网卡 → 属性 → 双击"Internet 协议版本 4 (TCP/IPv4)"。
    2. 确认勾选的是"自动获得 DNS 服务器地址"；如果家里路由器 DNS 不理想，选"使用下面的 DNS 服务器地址"填 223.5.5.5 和 119.29.29.29。
    3. 确定保存，然后清缓存：
    ipconfig /flushdns

    macOS 用：

    networksetup -getdnsservers Wi-Fi
networksetup -setdnsservers Wi-Fi Empty
sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder
    预期结果：ipconfig /all 里的 DNS 服务器指向路由器或你填的公共 DNS，不再是 127.0.0.1。
    失败怎么办？
    DNS 改完还是解析失败，用 nslookup www.baidu.com 看具体报错；如果解析到陌生 IP，怀疑被劫持，看「打开网页要等很久 / DNS 被劫持怎么判断」。

  5. 清理被劫持的路由表

    目的：这是"卸载了还断网"最常见的原因——工具把默认路由（0.0.0.0）指向了虚拟网卡，虚拟网卡删了，默认路由却还在。

    操作：查看当前路由表：

    route print -4

    重点看"IPv4 路由表"里的 0.0.0.0 那一行：

    • 正常：接口指向你的真实网卡，网关是你家路由器地址。
    • 异常：出现两条 0.0.0.0，或度量值（Metric）更小的那条接口是个陌生/已删除的地址。

    如果发现异常路由，删除它（把 <目标> 换成实际看到的地址，只删你能确认是工具留下的那一条）：

    route delete 0.0.0.0

    然后让 Windows 重新获取默认路由：

    ipconfig /release
ipconfig /renew
    预期结果：route print -4 里 0.0.0.0 的默认路由只剩一条，网关是路由器地址；ping 路由器IP 和 ping 223.5.5.5 都通。
    失败怎么办？
    不确定该删哪一条时不要瞎删——先断开 Wi-Fi 再重新连接（这一步会重建默认路由）；或者用下面的步骤 6 做整体重置。企业设备上路由由 IT 下发，请联系 IT。

  6. 重置网络栈（Winsock / IP / 网络重置）

    目的：前面都清干净了还不通，说明 Winsock 目录或 TCP/IP 栈被工具的过滤器驱动改坏了。

    操作：以管理员身份打开命令提示符，依次执行：

    netsh winsock reset
netsh int ip reset
ipconfig /flushdns

    然后必需重启电脑。

    如果重启后仍不通，再用系统自带的整体重置：设置 → 网络和 Internet → 高级网络设置 → 网络重置 → 立即重置（会重装所有网卡驱动并重启）。

    预期结果：重启后网卡正常工作，能获取到 IP、能解析域名、能打开网页。
    失败怎么办？
    网络重置后网卡驱动没了、连不上网，用手机 USB 共享网络给电脑联网，再到网卡厂商官网或电脑厂商官网下载对应驱动安装。

  7. 验证并做收尾检查

    目的：确认不是"看着好了"，而是真的恢复。

    操作：逐条执行：

    ipconfig /all
ping 你的路由器IP
ping 223.5.5.5
ping www.baidu.com
route print -4

    然后打开浏览器访问 2-3 个不同网站。另外检查一处容易被忽略的地方——hosts 文件是否被工具写过条目：用记事本以管理员身份打开 C:\Windows\System32\drivers\etc\hosts，除了以 # 开头的注释行和系统默认行，其他条目一律删掉再保存。

    预期结果：四条 ping/解析命令都正常，浏览器能打开网页，hosts 文件只剩注释行。
    失败怎么办？
    能 ping 通 IP、打不开域名 = DNS 问题，回步骤 4；能 ping 通外网、浏览器打不开 = 代理问题，回步骤 3。
