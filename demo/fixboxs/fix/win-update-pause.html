Windows 自动更新太烦，怎样安全暂停或临时关闭

⚠
⚠️ 需谨慎：Windows 更新包含安全补丁和驱动修复。本文只建议临时暂停，不提供永久关闭方案，也不建议安装来源不明的“更新屏蔽器”。暂停时间越长，漏洞和兼容风险越高。

💡 一句话结论

优先用「设置 → Windows 更新 → 暂停更新」；只需要避开一两天，就用下方 BAT 选择“临时暂停 24 小时”。脚本会创建自动恢复任务，24 小时后把 Windows Update 服务恢复，避免电脑长期脱离安全更新。

⚡ 30 秒快速排查（先试这个）

  1. 如果只是不想工作时自动重启，先设置“活动时间”，并选择“尽快重启”之外的合适时段。
  2. 如果一两天内不能更新，打开「设置 → Windows 更新 → 暂停更新」，选择最短够用的时间。
  3. 如果需要立即暂停 24 小时，运行下方 BAT 选择 [2]；恢复时选择 [1]，或等待自动恢复。

小白一键修复

不想研究原因，就下载脚本，右键选择“以管理员身份运行”。脚本执行前仍会再次确认。

下载 Windows 更新开关（.bat）
  • 适合Windows 10/11 个人电脑，临时需要避开自动更新、重启或更新下载。
  • 脚本会选择 [2] 后创建 24 小时后的系统计划任务，临时禁用 Windows Update 服务；到时自动恢复服务并删除任务。
  • 运行前保存文档，确认未来 24 小时不依赖新安全补丁。
  • 注意这不是永久关闭更新；单位统一管理的电脑不要运行，组策略也可能立即把服务恢复。
运行方式：下载后先解压（如有），右键 BAT 文件 → 以管理员身份运行 → 阅读提示后选择 Y。浏览器若提示“不常见文件”，请先核对文件名与下方源码。若浏览器无法下载，点“复制全部脚本”，粘贴到记事本，保存类型选择“所有文件”，文件名以 .bat 结尾。

@echo off
chcp 65001 >nul
setlocal EnableExtensions
title 修盒子 - Windows 更新开关

fltmc >nul 2>&1
if errorlevel 1 (
  echo 正在请求管理员权限...
  powershell -NoProfile -Command "Start-Process -FilePath '%~f0' -Verb RunAs"
  exit /b
)

if /I "%~1"=="/restore" goto :restore_mode

echo ============================================================
echo 修盒子 - Windows 更新开关
echo ============================================================
echo [1] 开启或恢复 Windows 更新
echo [2] 临时暂停 24 小时，到期自动恢复
echo [Q] 退出
echo.
echo 不会永久关闭更新，不会修改组策略或删除个人文件。
echo 企业、学校或单位统一管理的电脑请先联系 IT。
echo.
choice /C 12Q /N /M "请选择 [1/2/Q] "
if errorlevel 3 goto :cancelled
if errorlevel 2 goto :pause_update
if errorlevel 1 goto :enable_update
goto :cancelled

:enable_update
echo.
choice /C YN /N /M "确认开启更新服务并取消定时恢复？[Y/N] "
if errorlevel 2 goto :cancelled
call :restore_services
schtasks /Delete /TN "Fixbox\RestoreWindowsUpdate" /F >nul 2>&1
echo.
echo Windows 更新服务已恢复为手动启动并已尝试启动。
start "" ms-settings:windowsupdate
echo 请在设置页面点击“检查更新”；若显示“暂停更新”，再点“恢复更新”。
goto :end

:pause_update
echo.
echo 只会暂停 24 小时，到期后计划任务会自动恢复服务。
echo 暂停期间无法获取安全补丁，请勿在联网办公电脑长期使用。
choice /C YN /N /M "确认临时暂停 24 小时？[Y/N] "
if errorlevel 2 goto :cancelled

for /f %%I in ('powershell -NoProfile -Command "(Get-Date).AddHours(24).AddMinutes(1).ToString('HH:mm')"') do set "RESTORE_AT=%%I"
if not exist "%ProgramData%\Fixbox" mkdir "%ProgramData%\Fixbox" >nul 2>&1
copy /Y "%~f0" "%ProgramData%\Fixbox\manage-windows-update.bat" >nul

echo.
echo [1/3] 创建自动恢复任务，计划时间 %RESTORE_AT% ...
schtasks /Create /TN "Fixbox\RestoreWindowsUpdate" /TR "C:\ProgramData\Fixbox\manage-windows-update.bat /restore" /SC ONCE /ST %RESTORE_AT% /RU SYSTEM /RL HIGHEST /F >nul
if errorlevel 1 (
  echo 创建自动恢复任务失败，未暂停更新。
  goto :end
)

echo [2/3] 停止更新相关服务...
net stop usosvc /y >nul 2>&1
net stop wuauserv /y >nul 2>&1
net stop bits /y >nul 2>&1

echo [3/3] 临时禁用 Windows Update 服务...
sc config wuauserv start= disabled >nul 2>&1
sc config bits start= demand >nul 2>&1
sc config usosvc start= demand >nul 2>&1

echo.
echo 已临时暂停 Windows 更新。系统安全中心仍可能提示更新风险。
echo 如需立即恢复，请重新运行本脚本并选择 [1]。
goto :end

:restore_mode
call :restore_services
if not exist "%ProgramData%\Fixbox" mkdir "%ProgramData%\Fixbox" >nul 2>&1
>>"%ProgramData%\Fixbox\windows-update-restore.log" echo %DATE% %TIME% Windows Update services restored by scheduled task.
schtasks /Delete /TN "Fixbox\RestoreWindowsUpdate" /F >nul 2>&1
endlocal & exit /b 0

:restore_services
echo.
echo 正在恢复 Windows 更新服务...
sc config wuauserv start= demand >nul 2>&1
sc config bits start= demand >nul 2>&1
sc config usosvc start= demand >nul 2>&1
sc config cryptsvc start= auto >nul 2>&1
net start cryptsvc >nul 2>&1
net start bits >nul 2>&1
net start wuauserv >nul 2>&1
net start usosvc >nul 2>&1
exit /b 0

:cancelled
echo.
echo 已取消，没有修改任何设置。

:end
echo.
pause
endlocal

适用 / 不适用

适用：

  • 马上要演示、考试、直播或处理紧急工作，不想被更新重启打断。
  • 正在排查软件兼容问题，需要短时间冻结系统更新。
  • 当前网络按流量计费，想避开大批量更新。

不适用：

  • 想永久关闭安全更新 → 本文不提供，也不建议。
  • Windows 10 已结束常规支持，设备需要升级或采用微软公布的安全更新方案。
  • 公司、学校或单位设备由 IT 管理 → 按组织策略处理。
  • 更新已经卡住或反复安装失败 → Windows 更新卡住修复。

开始前确认

  • 已保存正在编辑的文件。
  • 知道电脑是个人设备，不受组织策略管理。
  • 24 小时内能重新联网并完成补丁安装。
  • 没有安装第三方“永久禁止更新”工具。
  • 磁盘剩余空间足够，暂停不是用来掩盖磁盘满或系统损坏问题。

怎么确认修好了

  • 设置页不再显示更新已暂停。
  • Fixbox\RestoreWindowsUpdate 自动恢复任务已执行或删除。
  • Windows Update 服务不再是“已禁用”。
  • 能重新检查并安装更新，工作时段不再突然重启。

还是不行？

  • 设置里没有暂停选项 → 可能是组织策略或系统版本限制，用 24 小时临时暂停或联系 IT。
  • 服务刚恢复又被关掉 → 检查第三方优化软件和单位策略。
  • 更新反复失败 → Windows 更新卡在 0% / 一直失败。
  • 系统盘空间不足 → C 盘爆红快满了，怎么安全清理。
  • 电脑整体很卡，误以为是更新导致 → 电脑越来越卡怎么办。

预防

  1. 用“活动时间”和“暂停更新”管理重启，不用永久禁用服务。
  2. 每月安排一次固定更新时间，及时安装安全补丁。
  3. 演示或出差前提前检查更新，不要到最后一刻才处理。
  4. 公司设备遵循组织更新窗口，个人脚本不能替代 IT 策略。
  5. 不下载“永久关闭 Windows 更新”的第三方工具或批处理合集。

分步骤

  1. 先设置活动时间

    目的：多数“自动重启”并不需要关闭更新，只需要让 Windows 避开工作时段。

    操作：

    1. 打开「设置 → Windows 更新 → 高级选项」。
    2. 开启“通知我以便安排重启”，并设置“活动时间”。
    3. 看到“需要重启”时，主动选择下班或空闲时间。
    预期结果：工作期间不再突然重启，更新仍能正常安装。
    失败怎么办？
    设备仍自动重启时继续步骤 2，并检查是否有单位策略。

  2. 使用设置中的暂停更新

    目的：这是微软支持的可恢复方式，优先于改服务或注册表。

    操作：

    1. 打开「设置 → Windows 更新」。
    2. 在“暂停更新”区域选择 1 周、2 周或系统允许的期限。
    3. 记下恢复日期。
    预期结果：页面显示更新已暂停，并给出恢复日期。
    失败怎么办？
    Home 版本可选项较少是正常的；改用步骤 3 的 24 小时临时暂停。

  3. 临时暂停 24 小时

    目的：在不永久关闭更新的前提下，给当前任务留出完整时间窗口。

    操作：

    1. 下载 manage-windows-update.bat。
    2. 右键选择“以管理员身份运行”。
    3. 选择 [2] 临时暂停 24 小时，再选择 Y。
    4. 脚本会创建 Fixbox\RestoreWindowsUpdate 计划任务，并把脚本复制到 C:\ProgramData\Fixbox。
    预期结果：Windows Update 服务被临时禁用，任务计划程序里能看到自动恢复任务。
    失败怎么办？
    如果创建任务失败，脚本不会暂停更新；检查系统时间和任务计划程序服务，或改回步骤 2。

  4. 需要时立即恢复

    目的：不必等满 24 小时，也不能把暂停误当成永久设置。

    操作：

    1. 重新运行同一个 BAT。
    2. 选择 [1] 开启或恢复 Windows 更新。
    3. 按 Win + R 输入 taskschd.msc，确认 Fixbox\RestoreWindowsUpdate 已被删除。
    预期结果：更新服务恢复为按需启动，设置页可以检查更新。
    失败怎么办？
    打开 Windows 更新被关闭了，怎么重新开启 按步骤检查服务和策略。

  5. 暂停结束后完成补丁

    目的：补回暂停期间遗漏的安全更新。

    操作：

    1. 到「设置 → Windows 更新」点击“检查更新”。
    2. 安装完成后重启，再次检查，直到没有新更新。
    3. 如果下载卡住，按 Windows 更新卡住修复 处理。
    预期结果：更新历史显示补丁安装成功，系统恢复受支持状态。
    失败怎么办？
    空间不足先清理 C 盘；公司设备联系 IT；长期失败不要继续叠加“屏蔽工具”。
