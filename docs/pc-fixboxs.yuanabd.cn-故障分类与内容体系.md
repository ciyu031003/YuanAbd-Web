## 0. 文档目标与交付边界

本文档只回答一个问题：**pc-fixboxs.yuanabd.cn 上到底要放哪些内容、怎么分类、每篇怎么写、谁来审、什么时候淘汰。**

| 项 | 说明 |
|---|---|
| 交付物 | 本文档一份（内容侧设计），**不含代码、不含页面实现、不改任何现有文件** |
| 服务对象 | 内容编辑、教程作者、审稿人、后续负责页面/搜索实现的开发者 |
| 站点形态 | 纯静态站（`demo/` 下 HTML + `css/` + `js/`，无框架、无构建，仅 `build-portal.cjs` 做单文件内联） |
| 视觉依据 | `DESIGN-SYSTEM.md` + `demo/css/tokens.css`（暖白 `#FFFDF7` / 阳光黄 `#FFD84D` / 天蓝 `#79CFFF` / 薄荷 `#91E6C1` / 珊瑚 `#FF9278`，中文 Noto Sans SC，正文 ≥16px） |
| 合规 | 页脚必须含 ICP 备案：赣ICP备2024031528号-2（链接 https://beian.miit.gov.cn/ ） |

**本文档不做的事：** 不定路由规则、不定 URL 结构、不定搜索实现（是否用 Pagefind/Lunr/自研）、不定数据文件格式的代码层细节。这些由实现方按本文档的字段定义落地。

## 1. 站点定位与读者模型

### 1.1 一句话定位

> 用户带着「我电脑 / 我网络出问题了」进来，用口语词搜到一篇教程，跟着分步骤操作，把问题解决掉。

这决定了两条铁律：

1. **入口是搜索，不是导航。** 用户不会先读分类目录，而是直接搜「电脑开机黑屏只有鼠标」。所以 IA 的第一职责是**让每篇文章被口语词命中**，第二职责才是给人看的目录。
2. **成功标准是「问题消失」，不是「看懂了」。** 每篇文章必须在 30 秒内给出可执行动作，再展开原理。

### 1.2 读者画像

| 画像 | 占比预估 | 特征 | 内容要求 |
|---|---|---|---|
| 家庭用户 / 学生 | ~55% | 只会用图形界面，怕命令，怕搞坏 | 命令必须可复制、有截图位、有「失败怎么办」 |
| 办公白领（含远程办公） | ~25% | 有公司管控设备，需要合规边界 | 明确标注「企业设备请联系 IT」 |
| 小型办公室 / 店主 | ~12% | 要管路由器、打印机、几台电脑 | 需要路由器/共享打印/局域网类内容 |
| 动手能力强 / 开发者 | ~8% | 要命令、要日志、要原理 | 每篇末尾给「进阶排查」与命令清单 |

### 1.3 检索意图分布（决定文章写法）

| 意图类型 | 示例查询 | 文章应给的第一个东西 |
|---|---|---|
| 症状描述型 | 「电脑开机黑屏只有鼠标」 | 30 秒快速排查 |
| 报错原文型 | 「netsh winsock reset 是什么」 | 命令解释 + 适用场景 |
| 数字/IP 型 | 「192.168.1.1 打不开」 | 逐条排除（网关是否对、网段是否对） |
| 对比选择型 | 「光猫桥接还是路由器拨号」 | 判断表 + 结论 |
| 操作求助型 | 「IP 地址冲突怎么查是哪台设备」 | 查法（ARP 表 / 路由器客户端列表） |
| 恐惧型 | 「电脑中病毒了怎么办」 | 先止损（断网、备份），再清除 |

## 2. 分类体系（IA 内容侧）

### 2.1 三级结构

```
领域 Domain（12 个，稳定不变，对应导航一级）
└── 故障类 Category（3–8 个/领域，对应导航二级 + 聚合页）
    └── 教程条目 Article（对应单篇教程，可被多个故障类关联，但只有一个主归属）
```

**结构规则（必须遵守）：**

| 规则 | 内容 |
|---|---|
| R1 唯一主归属 | 每篇文章只能有一个 `domain` + 一个 `category`；跨域需求靠 `related[]` 关联，不靠多重归类 |
| R2 领域稳定 | 领域是导航骨架，**不随热点增删**；新问题优先塞进现有故障类 |
| R3 故障类可增长 | 故障类允许新增（如「Windows on ARM」），但一个领域超过 8 个就必须拆分或合并 |
| R4 分类面向「故障现象」 | 不按软件品牌分类（不做「微信专区」「钉钉专区」），品牌只作为文章内的关键词与标签 |
| R5 系统维度不进分类 | 系统（Win10/11、macOS 版本）是文章的 `os` 字段与筛选项，不是分类层级 |

### 2.3 领域排序与导航建议

| 顺序 | 领域 | 理由 |
|---|---|---|
| 1 | 网络基础 | 最高频、最影响「能不能干活」，且是所有网络类问题的总入口 |
| 2 | Windows 系统与开机 | 存量设备最多 |
| 3 | 路由器与家庭网络 | 与网络基础强相关，用户常在两者间来回跳 |
| 4 | IP 与 DNS | 网络类的深水区，承接上两者的分流 |
| 5 | Windows 软件与性能 | 日常抱怨最多 |
| 6 | macOS 系统与开机 | 苹果用户单独成线 |
| 7 | macOS 软件与性能 | 同上 |
| 8 | 硬件与主机 | 需要动手拆机，风险高，放在中后段 |
| 9 | 外设 | 长尾多、单篇价值中等 |
| 10 | 代理与 VPN | 合规敏感，需要专门提示 |
| 11 | 账号与安全 | 恐惧型搜索，转化率高 |
| 12 | 数据与备份 | 最紧急但最低频，必须在导航中足够显眼（建议首屏单独入口） |

> **导航提示：** 「数据与备份」虽然排最后，但属于**高紧急度**内容，建议在首页/搜索结果页做固定横幅：「文件误删了？先别写入磁盘 → 误删文件恢复」。

# Wi-Fi 已连接但无法上网，怎么一步步排查

> ⚠️ 本文会修改系统网络设置。操作前建议把当前 IP、DNS 配置截图保存，以便随时还原。

## 一句话结论

「已连接」只说明电脑和路由器握手成功，不代表路由器能上网——**先判断是全家断网还是只有这台电脑不行**，再决定往哪个方向修。

## 30 秒快速排查

1. **用手机连同一个 Wi-Fi 试一次。** 手机也上不了 → 是路由器或宽带的问题，直接看 [家里所有设备都上不了网](#)，不要继续折腾电脑。
2. **重启路由器和光猫。** 两者都断电 30 秒，先开光猫、等指示灯稳定后再开路由器，再等 2 分钟。
3. **Windows：设置 → 网络和 Internet → 高级网络设置 → 网络重置 → 立即重置**，重启电脑。（macOS：关闭 Wi-Fi 再打开，或重启。）
4. **换手机热点试一次。** 连热点能上网 → 问题在路由器/宽带侧；连热点也不行 → 问题在电脑网卡或系统。

## 适用与不适用

**适用：**
- Wi-Fi 图标显示已连接，但浏览器打不开网页、任务栏出现地球/叹号图标
- 手机能上网，同一 Wi-Fi 下电脑不行
- 提示「无 Internet 访问权限」「网络受限」

**不适用（请转对应文章）：**
- Wi-Fi 列表里根本没有自家网络 → [Wi-Fi 列表里找不到自家网络](#)
- 所有设备（含手机）都上不了网 → [家里所有设备都上不了网](#)
- 只有浏览器打不开、微信/QQ 正常 → [只有浏览器上不了网](#)
- 网页打不开但 QQ 能上 → [网页打不开但 QQ 能用](#)

## 前置检查

- [ ] 手机连同一 Wi-Fi 能正常上网（确认不是宽带整体故障）
- [ ] 知道自家路由器的管理地址与登录密码（后面可能需要）
- [ ] Windows 操作需以**管理员**身份打开命令提示符：开始菜单搜索「cmd」→ 右键 → 以管理员身份运行
- [ ] 已保存正在编辑的文档，部分操作需要重启

## 分步骤排查

### 第 1 步：确认故障范围（2 分钟）

**目的**：分清「路由器/宽带问题」和「这台电脑的问题」，避免修错方向。

**操作**：用手机连同一个 Wi-Fi，打开任意网页；再打开一个视频 App 播放。

**预期结果**：
- 手机正常 → 继续第 2 步（问题在电脑侧）
- 手机也不行 → 转 [家里所有设备都上不了网](#)，本文后续步骤不适用

**失败怎么办**：手机连的是流量而不是 Wi-Fi 时，请先关闭移动数据再测一次。

### 第 2 步：看电脑拿到了什么 IP（3 分钟）

**目的**：判断电脑是否真的从路由器拿到了有效地址。

**操作**（Windows，管理员命令提示符）：

```bat
ipconfig /all
```

macOS（终端）：

```bash
ifconfig en0 | grep "inet "
netstat -nr \| grep default
```

**预期结果**：
- 看到形如 `192.168.x.x` 的 IPv4 地址，且「默认网关」是路由器地址（常见 192.168.1.1 / 192.168.0.1 / 192.168.31.1）
- 能 ping 通网关：`ping 192.168.1.1`（把地址换成你的实际网关）

**失败怎么办**：
- 地址是 `169.254.x.x` → 电脑没拿到 DHCP 租约，转 [电脑获取不到 IP 地址](#)
- 完全没有 IPv4 地址 → 网卡或驱动问题，转 [电脑没有 WLAN 选项](#)

### 第 3 步：续租 IP 并刷新 DNS（3 分钟）

**目的**：清掉可能已失效的地址租约与错误解析缓存。

**操作**（Windows，管理员命令提示符，逐条执行）：

```bat
ipconfig /release
ipconfig /renew
ipconfig /flushdns
```

macOS（终端）：

```bash
sudo ipconfig set en0 DHCP
sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder
```

**预期结果**：`ipconfig /renew` 返回新的 IPv4 地址；刷新 DNS 提示「已成功刷新 DNS 解析缓存」。

**失败怎么办**：报「媒体已断开」说明链路层没通（网线/无线连接问题）；`/renew` 长时间无响应说明路由器 DHCP 没响应，重启路由器后重试。

### 第 4 步：换 DNS 服务器测试（5 分钟）

**目的**：排除 DNS 解析异常——这是「显示已连接但打不开网页」最常见的原因之一。

**操作**（Windows）：
1. 右键任务栏网络图标 → 网络和 Internet 设置 → 高级网络设置 → 找到你的网卡 → 编辑 → IP 分配「自动 (DHCP)」→ DNS 服务器分配改为「手动」→ 打开 IPv4。
2. 首选 DNS 填 `223.5.5.5`（阿里公共 DNS），备用填 `119.29.29.29`（腾讯公共 DNS）→ 保存。

macOS（终端，Wi-Fi 服务名可用 `networksetup -listallnetworkservices` 查询）：

```bash
networksetup -setdnsservers Wi-Fi 223.5.5.5 119.29.29.29
networksetup -getdnsservers Wi-Fi
```

**预期结果**：能正常打开网页；`nslookup www.baidu.com` 能返回 IP 地址。

**失败怎么办**：改回自动获取（macOS：`networksetup -setdnsservers Wi-Fi Empty`）；若换 DNS 后仍打不开，继续第 5 步。

### 第 5 步：排查代理与加速软件（5 分钟）

**目的**：代理设置残留是「网络看着正常但上不了网」的高频原因。

**操作**（Windows）：
1. 设置 → 网络和 Internet → 代理：关闭「自动检测设置」与「使用代理服务器」。
2. 管理员命令提示符查看系统级代理：`netsh winhttp show proxy`

macOS：系统设置 → 网络 → 详细信息 → 代理，关闭所有代理开关。

**预期结果**：关闭后网页恢复正常。

**失败怎么办**：如果刚装过加速器、抓包或虚拟网卡软件，转 [装了抓包/加速工具后全网断网](#)。

### 第 6 步：重置网络栈（10 分钟，需重启）

**目的**：把网络组件恢复到初始状态，解决协议栈损坏类问题。

**操作**（Windows，管理员命令提示符，逐条执行后重启）：

```bat
netsh winsock reset
netsh int ip reset
ipconfig /flushdns
shutdown /r /t 0
```

**预期结果**：重启后网络恢复正常。

**失败怎么办**：重启后仍不行，说明不是本机协议栈问题，回到第 1 步重新判断范围，或联系运营商/单位 IT。

## 验证是否解决

按顺序确认全部通过才算解决：

1. 能正常打开 2–3 个不同网站（不只是浏览器首页）
2. `ping 223.5.5.5` 有稳定回复，`ping www.baidu.com` 能解析出 IP 并回复
3. 任务栏网络图标不再显示叹号/地球

## 预防

1. 路由器与光猫放在通风处，每季度断电重启一次。

## 7. 内容生产与维护流程

### 7.1 来源与可信度分级

每篇文章的 `sources[]` 中每条来源必须标注 `type`，按下列分级：

| 级别 | type | 说明 | 可否作为唯一依据 | 示例 |
|---|---|---|---|---|
| A 级 | `official` | 操作系统/硬件厂商官方文档 | ✅ 可以 | Microsoft Learn、Apple 支持、Intel/AMD/NVIDIA 官方、主板厂商手册 |
| B 级 | `vendor` | 设备或软件厂商官方说明 | ✅ 可以（限该厂商设备） | 路由器厂商固件说明、打印机厂商驱动页、NAS 厂商文档 |
| C 级 | `standard` | 标准与协议文档 | ✅ 可以（限协议细节） | IETF RFC（如 RFC 2131 DHCP）、IEEE 802.11 相关标准 |
| D 级 | `tested` | 编辑实测复现 | ✅ 可以（需注明测试环境） | 「Windows 11 23H2 + 某型号路由器实测」 |
| E 级 | `community` | 社区讨论、论坛、问答 | ❌ 不可单独使用，必须由 A/B/C/D 级交叉验证 | 技术论坛、Stack Exchange |
| F 级 | `unknown` | 来源不明或转载 | ❌ 禁止引用 | 内容农场、无出处的「教程」 |

**硬性规则：**

| 规则 | 内容 |
|---|---|
| S1 | 每篇文章至少 **1 条 A/B/C 级 + 1 条 D 级（实测）**，纯理论文章可豁免 D 级但需在文末注明 |
| S2 | 涉及注册表、组策略、`netsh`、磁盘/分区操作的，必须引用 A 级或 B 级来源 |
| S3 | 命令必须**实际执行验证**过再写入，并注明是否需要管理员权限 |
| S4 | 不确定的内容写「以厂商文档为准」并给出官方链接，**绝不编造**路径、注册表项或参数 |
| S5 | 引用社区方案时，必须说明「该方案适用于 X 场景，未在 Y 场景验证」 |
| S6 | 所有外链在发布前与每季度巡检时验证可达（404 即替换或降级为文内说明） |

| P2 标注 | 用统一色块高亮（暖白底上使用阳光黄 `#FFD84D` 描边 + 珊瑚 `#FF9278` 箭头），序号圆圈用天蓝 `#79CFFF` |
| P3 序号对应 | 截图上的序号必须与正文步骤号一致，禁止「如图所示的那个按钮」这类模糊指代 |
| P4 暗色模式 | 系统设置类截图提供浅色版即可；若目标系统默认深色，需补一张深色版 |
| P5 版本标注 | 每张截图下方标注系统版本与截取日期，如「Windows 11 23H2 · 2026-10」 |
| P6 必须脱敏 | 隐藏或打码：MAC 地址、序列号/服务标签、Wi-Fi 名称（SSID）、公网 IP、真实用户名、邮箱、手机号、二维码、公司内网域名与主机名 |
| P7 脱敏手法 | 用同色块覆盖而非模糊（模糊可被还原）；脱敏后的示例值保持格式合法（如 MAC 用 `AA:BB:CC:11:22:33`） |

### 7.4 版本与「最近更新」策略

| 场景 | 处理方式 | 是否改 `updated` | 是否 +0.1 版本 |
|---|---|---|---|
| 修正错别字、调整排版 | 直接改 | ❌ 否 | ❌ 否 |

| 命令/路径失效需替换 | 改正文 + 更新日志注明「因 XX 版本变更」 | ✅ 是 | ✅ 是 |

| 文章被判定过时但仍可参考 | 顶部加「⚠️ 本文基于 X 版本，新版本可能不同」提示条 | ❌ 否（另记 `stale_since`） | ❌ 否 |
| 文章已不适用 | 归档，见 §7.5 | ❌ 否 | ❌ 否 |

- 显示「最近更新：YYYY-MM-DD」；超过 **12 个月**未更新的文章，在标题下显示「本文有一段时间未更新，请以系统实际界面为准」。

- 文章列表页默认按「最近更新」倒序，但「高频必读」置顶位由编辑人工指定。

### 7.5 失效教程的归档规则

| 触发条件 | 处理 | 保留期 |
|---|---|---|
| 对应的系统/软件版本已停止支持且无用户 | 归档（`status: archived`），页面顶部显示归档说明与替代文章 | 永久保留 URL，页面可访问 |

| 4 | 未经授权对他人网络/设备抓包、扫描、渗透 | 可能违反《网络安全法》《刑法》相关条款 | 只写「对自有设备」的排查，且明确授权前提 |

| 7 | 引导用户关闭全部安全防护（如关闭杀毒、关闭防火墙、全局关闭 Gatekeeper） | 显著降低安全性 | 只允许「临时关闭并说明恢复时间」，且必须写恢复步骤 |
| 8 | 编造的命令、路径、注册表项、错误码含义 | 误导用户 | 不确定就写「以厂商文档为准」并给官方链接 |
| 9 | 鼓励自行拆解带电设备、拆解电池（尤其鼓包电池） | 起火/触电风险 | 明确「电池鼓包立即停用并送修」 |
| 10 | 承诺性表述（100% 修复、一键彻底解决、永久有效） | 不诚信且易引发投诉 | 改为「多数情况可解决」「若无效请转到 X」 |
| 11 | 未脱敏的截图（含真实 MAC、序列号、Wi-Fi 名、内网域名） | 隐私与安全风险 | 按 §7.2 P6/P7 脱敏 |

### 8.2 代理 / VPN 类内容的中国大陆合规提示写法

**适用范围：** 领域 D10（代理与 VPN）下所有文章，以及任何正文中出现「代理」「VPN」「PAC」「加速器」「抓包」等词的文章。

**统一提示块（放在正文最前端、一句话结论之前，样式为浅色信息条）：**

```markdown
> 📌 **合规提示**
> 本文仅介绍**企业/校园网内正常使用代理、VPN 访问内部系统**，以及**个人排查本机代理设置异常**的方法。
> 请遵守《中华人民共和国网络安全法》及所在单位网络管理规定，仅对**你本人拥有或已获授权**的设备与网络进行操作。
> 如设备由单位统一管理，请优先联系单位 IT，不要自行修改网络与安全策略。
```

**写法要求：**

| # | 要求 |
|---|---|
| 1 | 只描述「本机代理设置异常如何排查与恢复」，不提供任何用于规避网络管理的配置教程 |
| 2 | 企业 VPN 的服务器地址、端口、证书、账号**一律以单位 IT 提供的信息为准**，文中不得给出具体境外服务器地址 |
| 3 | 不出现「科学上网」「翻墙」「梯子」「机场」等表述，也不作为关键词/别名收录 |
| 4 | 抓包类内容限定为「排查本人设备网络问题的合法抓包」，并写明需在自有网络与自有设备上进行 |
| 5 | 涉及企业管控设备时，统一表述为「请勿尝试绕过管控，请联系 IT」 |
| 6 | 页脚保留 ICP 备案号与合规声明链接 |
| 7 | 审核时由第二人复核合规项（§7.3 E 段）后方可发布 |

## 10. 关键取舍与后续动作

### 10.1 本方案做的关键取舍

| # | 取舍 | 决策 | 理由 |
|---|---|---|---|
| 1 | 分类维度 | 按**故障现象**分类，不按软件品牌/系统版本分类 | 用户搜的是现象（「上不了网」），不是「微信」或「Win11」；品牌与版本作为字段/标签处理，避免分类爆炸 |
| 2 | 领域数量 | 固定 12 个，不轻易增删 | 领域是导航骨架，频繁变动会让 URL 与内链失效；新问题优先塞进现有故障类 |
| 3 | 系统维度 | Win10/11 合并、macOS 用「12+」区间 | 版本号写进分类会迅速过时；用 `os[]` 字段筛选即可 |
| 4 | 域名归属 | 代理/VPN 单独立域（D10）而非并入网络基础 | 合规提示是刚性要求，独立成域便于统一挂提示块与统一审核 |
| 5 | 风险分级 | 用三级（安全/需谨慎/有数据风险）而非更细的评分 | 三级能直接映射到页面提示样式与审核强度，再多用户也不看 |
| 6 | 文章结构 | 固定 10 段，30 秒快速排查必须前置 | 用户带着急事进来，先给能立刻试的动作，原理后置 |
| 7 | 数据与备份排序 | 导航排最后，但要求首页单独紧急入口 | 频次低但紧急度最高，必须显眼而不能靠目录层级 |
| 8 | 标题不写年份与版本 | 由 `updated` 与 `os[]` 承担时效表达 | 避免文章「看起来过期」，也避免为改标题而改 slug |
| 9 | 归档不删除 | 保留 URL + 归档说明页 | 保护外链与搜索收录，避免 404 |
| 10 | 命令真实优先 | 不确定一律写「以厂商文档为准」+ 官方链接 | 宁可少写一条命令，也不编造路径或注册表项 |
| 11 | 拒绝「一键修复」类内容 | 只推荐系统自带与知名厂商工具 | 这类工具是二次故障与木马的主要来源 |
| 12 | 企业场景不写绕过 | 统一表述为「请联系 IT」 | 合规红线，且绕过管控会给用户带来实际风险 |
