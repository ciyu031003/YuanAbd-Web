## 0.1 文档目标

本文档回答「pc-fixboxs 这个站要长什么样、怎么组织、用户怎么用」三个问题，产出**可评审、可直接开工**的设计规格。

站点一句话定位：

> **电脑与网络故障的自助排障手册**——把「我电脑坏了」翻译成「照着做就能修好」。

覆盖范围：Windows（主机 + 笔记本）、macOS（Mac mini/iMac/MacBook）、外设（打印机/显示器/键鼠/蓝牙/U 盘）、
家庭网络（路由器、Wi-Fi、网线、IP 冲突、DNS）、代理与 VPN。

**设计的第一性原理**：用户进来的时候是**焦虑的**，设备是**坏的**，耐心是**零**的。
所以这个站的设计目标不是「好看」，而是**最快把用户送到能解决问题的那个步骤上**。

## 2. 定位、用户与核心场景

### 2.1 目标用户（三类）

| 类型 | 占比估计 | 特征 | 设计要满足 |
|---|---|---|---|
| **普通用户**（主力） | ~65% | 不懂术语，只会描述现象（「上不了网」「卡住了」） | 口语搜索 + 症状向导 + 零术语的步骤 |
| **半懂用户** | ~25% | 知道「DNS」「代理」这些词，但不会排查 | 术语可搜 + 命令行速查 + 进阶分支 |
| **IT 顺手党 / 帮人修电脑的** | ~10% | 要快、要准、要能直接复制命令 | 命令一键复制 + 深链接 + 打印/收藏 |

### 2.2 核心使用场景（设计必须覆盖）

| # | 场景 | 设备状态 | 设计应对 |
|---|---|---|---|
| S1 | **电脑还能用，但网络断了**，用手机搜 | 手机浏览 | 移动优先、首屏就是搜索框、结果页零跳转成本 |
| S2 | **电脑开不了机 / 黑屏**，用另一台设备查 | 另一台设备 | 教程页可打印/可分享链接；步骤短句、不依赖截图才能懂 |
| S3 | **照着做但没修好** | 电脑可用 | 「仍未解决」分流区 → 下一篇教程 / 何时送修 |
| S4 | **做到一半忘了做到哪** | 电脑可用 | 步骤勾选 + 本地进度记忆（localStorage） |
| S5 | **帮家人远程指导** | 双方设备 | 每步一个短链接（锚点 `#step-3`）+ 可复制文本 |

### 2.3 设计原则（五条，冲突时按此排序）

1. **搜索优先（Search-first）**——首页第一个像素级交互元素是搜索框，不是 Banner。
2. **结论先行（Answer-first）**——每篇教程第一屏就给出「一句话结论 + 30 秒快速排查」，不让用户滚动 3 屏才看到答案。
3. **一步一屏（One step at a time）**——步骤是页面的主体，每一步只有一件事、一个预期结果、一个失败出口。
4. **风险可见（Risk-aware）**——有数据风险的操作必须在**点击前**、**步骤标题上**、**命令块旁**三处提示，不用颜色作为唯一信号。
5. **降级可用（Resilient）**——JS 失效、搜索索引加载失败、图片不显示时，分类浏览与正文仍然完全可用。

### 2.4 非目标（本期不做）

- ❌ 不做用户账号 / 登录体系（内容站无需账号）。
- ❌ 不做在线问答社区、评论、工单。
- ❌ 不做 AI 对话式诊断（可作为 Phase 4 演进，但首期不引入模型成本与幻觉风险）。
- ❌ 不做远程协助 / 远程控制（安全与合规风险高）。
- ❌ 不搬运、不镜像第三方付费内容；所有教程为原创或基于官方文档改写。

## 3. 信息架构（IA）

### 3.1 站点地图

```
pc-fixboxs.yuanabd.cn/
├─ /                              首页（搜索优先 + 症状入口 + 领域网格 + 热门）
├─ /search/?q=&domain=&os=&risk=  搜索结果页（支持 URL 直达，可分享）
├─ /wizard/                        症状向导（8 步问答 → 推荐 1–3 篇教程）
├─ /browse/                        全部领域总览（12 宫格）
│   └─ /browse/<domain>/           领域页（故障类 + 教程列表 + 本域热门）
│        └─ /browse/<domain>/<category>/
├─ /fix/<slug>/                    教程详情页 ★核心内容单元
├─ /tag/<tag>/                     标签聚合页（如 /tag/wifi/、/tag/蓝屏/）
├─ /tools/                         应急工具（命令速查 / 网络自检 / 代理自检 / 系统信息）
├─ /bookmarks/                     我的排障清单（localStorage，无需登录）
├─ /about/                         关于本站（内容来源、免责声明、纠错入口）
├─ /legal/privacy/ · /legal/disclaimer/
├─ /404.html
└─ /sitemap.xml · /robots.txt
```

设计取舍：
- **没有 `/os/windows/` 一级路径**。系统不是用户找东西的第一维度——用户先想的是「我遇到什么问题」，不是「我是什么系统」。
  系统降级为**筛选条件**（搜索页 `?os=`、教程页徽章）。
- **保留 `/tag/`**：标签是「症状」与「部件」的横切面（如 `蓝屏`、`Wi-Fi`、`驱动`），对 SEO 与内链有价值。
- **`/tools/` 单列**：网络故障场景下「命令速查」是高频刚需，值得独立成页并可离线收藏。

### 3.2 三级内容模型

```
领域 Domain（12 个，稳定不变）
  └─ 故障类 Category（75 个，每领域 6–7 个，可增删）
        └─ 教程 Article（300+ 篇，持续增长）
```

| 层级 | 数量级 | 页面 | 用户视角 |
|---|---|---|---|
| 领域 | 12 | `/browse/<domain>/` | 「我这属于哪一类问题」 |
| 故障类 | 75（每领域 6–7 个） | `/browse/<domain>/<category>/` | 「具体是哪个毛病」 |
| 教程 | 300+ | `/fix/<slug>/` | 「怎么修」 |

> 领域与故障类的完整清单（含 slug、图标、典型提问原话）见配套文档
> `docs/pc-fixboxs.yuanabd.cn-故障分类与内容体系.md`。

### 3.3 全局导航规则（与三站统一 Brand Shell 对齐）

```
┌──────────────────────────────────────────────────────────────┐
│ 修盒子 FIXBOX            领域  症状向导  工具  关于    [🔍 搜索] │  ← 顶栏 64px，滚动后吸顶
└──────────────────────────────────────────────────────────────┘
```

- **左上**：站点标识 `修盒子 FIXBOX`（返回首页）；桌面端右侧附一行小字「YUAN.ABD 出品」链接回主站。
- **右上**：搜索图标按钮（移动端）/ 常驻搜索框（桌面端 ≥1024px）。
- **主导航四项**：领域 / 症状向导 / 工具 / 关于——刻意保持 4 项，避免导航膨胀。
- **移动端**：汉堡菜单 → 全屏抽屉；搜索框固定在抽屉顶部。
- **页脚统一**：本站说明 + 领域快链 + 免责声明 + 纠错入口 + ICP 备案号 + 最近更新时间。

### 3.4 页面清单与优先级

| 优先级 | 页面 | 说明 |
|---|---|---|
| P0 | 首页 `/`、搜索页 `/search/`、教程页 `/fix/<slug>/`、领域页 `/browse/<domain>/` | MVP 必须，缺一不可 |
| P1 | 领域总览 `/browse/`、症状向导 `/wizard/`、标签页 `/tag/<tag>/`、404 | 体验完整度 |
| P2 | 工具页 `/tools/`、清单页 `/bookmarks/`、关于/隐私/免责 | 增强与合规 |

## 4. 视觉设计（Visual Design）

### 4.1 设计方向

**关键词：暖白纸感 · 薄荷绿 · 编辑式排版 · 安静的工具感**

| 维度 | 决策 | 理由 |
|---|---|---|
| 底色 | 暖白 `#FFFDF7`（沿用品牌 `--c-warm-white`） | 与三站同一张「纸」，长时间阅读不刺眼 |
| 主色 | **薄荷绿 `--c-mint` `#91E6C1`** | 品牌色板中唯一未被占用的色（黄=主站、蓝=Learn、橙=Travel），且语义天然指向「恢复正常 / 修好了」 |
| 气质 | 安静、可信、不喧哗 | 用户是来解决问题的，任何装饰都在拖慢他 |
| 排版 | 编辑式：大标题 + 舒适行距 + 明确层级 | 教程是「阅读型」内容，排版就是产品 |
| 插画 | **克制**：仅首页 Hero 一处抽象「线路 / 连接修复」几何插画 | 故障类内容不适合卡通吉祥物，容易显得不专业 |
| 图标 | 线性 SVG，1.5px 描边，24px 网格 | 与三站一致，**禁用 emoji 当图标**；内容体系文档「图标建议」列里的 emoji 只是速记标签，实现时必须替换为 SVG |

### 4.2 色彩令牌（新增 `demo/css/theme-fix.css`）

本站**不修改** `tokens.css`，只新增一份主题映射文件，复用既有 Semantic 槽位。

```css
:root{
  /* —— 主色槽位：薄荷绿 —— */
  --brand: var(--c-mint);        /* #91E6C1 大面积色块 / 插画 / 图表 */
  --brand-strong: #12805F;       /* 4.83:1 —— 正文链接、图标、小字号强调 */
  --brand-deep:   #0F766E;       /* 5.38:1 —— hover、标题强调 */
  --brand-soft:   #EAF9F2;       /* 淡底：信息卡、选中态 */
  --brand-ink:    #0B3B2E;       /* 浅薄荷底上的文字 */

  /* —— 风险分级（三色，语义固定，全站唯一） —— */
  --risk-safe:    #12805F;  --risk-safe-bg:    #EAF9F2;   /* 安全 */
  --risk-caution: #B45309;  --risk-caution-bg: #FFF6E2;   /* 需谨慎 */
  --risk-danger:  #C2410C;  --risk-danger-bg:  #FFEDE6;   /* 有数据风险 */

  /* —— 系统标识色（仅用于系统徽章，禁止用于正文） —— */
  --os-windows: #2A6FB5;
  --os-macos:   #3A4350;
  --os-router:  #7C63E8;

  /* —— 代码块 —— */
  --code-bg:   #F4F7F5;
  --code-line: rgba(18,128,95,.18);
  --code-ink:  #18202A;
}
```

### 4.3 对比度实测（WCAG 2.1 AA 校验，已逐项计算）

| 用途 | 前景 | 背景 | 实测对比度 | 结论 | 令牌 |
|---|---|---|---|---|---|
| 薄荷深阶（正文/链接） | `#12805F` | `#FFFDF7` | **4.83:1** | ✅ AA | `brand-strong` |
| 薄荷深阶（白底卡片） | `#12805F` | `#FFFFFF` | **4.91:1** | ✅ AA | `brand-strong` |
| 白字在薄荷深底（主按钮） | `#FFFFFF` | `#12805F` | **4.91:1** | ✅ AA | `btn label` |
| 墨绿深阶（hover/标题） | `#0F766E` | `#FFFDF7` | **5.38:1** | ✅ AA | `brand-deep` |
| 琥珀（需谨慎） | `#B45309` | `#FFFDF7` | **4.94:1** | ✅ AA | `risk-caution` |
| 琥珀在暖黄底 | `#B45309` | `#FFF6E2` | **4.67:1** | ✅ AA | `risk-caution on tint` |
| 砖红（有数据风险） | `#C2410C` | `#FFFDF7` | **5.09:1** | ✅ AA | `risk-danger` |
| 砖红在珊瑚淡底 | `#C2410C` | `#FFEDE6` | **4.56:1** | ✅ AA | `risk-danger on tint` |
| 次文字 | `#5C6673` | `#FFFDF7` | **5.73:1** | ✅ AA | `text-secondary` |
| 弱文字 | `#6E767E` | `#FFFDF7` | **4.53:1** | ✅ AA | `text-muted` |
| 薄荷正文在薄荷淡底 | `#12805F` | `#EAF9F2` | **4.52:1** | ✅ AA | `on tint` |

**关键决策：薄荷绿 `#91E6C1` 只做「面」，不做「字」。**
它作为正文前景色在暖白底只有 **1.5:1**，远达不到 AA。因此全站规则是：

| 薄荷绿 `#91E6C1` 允许 | 薄荷绿 禁止 |
|---|---|
| 大色块背景（配深墨文字） | 正文 / 链接文字 |
| 插画与图表填充 | 小图标描边（对比度 <3:1） |
| 进度条、标签底、状态点 | 作为唯一的状态信号 |
| hover 光晕、装饰性描边 | 细边框（视觉不可辨） |

### 4.4 风险三色（本站最重要的语义系统）

| 等级 | 色值 | 图标 | 文案模板 | 触发场景 |
|---|---|---|---|---|
| 安全 | `--risk-safe` | ✅ 勾 | 「可放心操作，随时可撤销」 | 重启、刷新 DNS、重置网络适配器 |
| 需谨慎 | `--risk-caution` | ⚠ 三角 | 「会短暂断网/需管理员权限，按步骤来」 | 改注册表、重置 Winsock、刷路由器固件 |
| 有数据风险 | `--risk-danger` | ⛔ 圆 | 「可能丢失数据，**先备份**再继续」 | 格式化、分区、磁盘修复、重装系统 |

**三重冗余规则**（无障碍要求，不能只靠颜色）：
1. 颜色（底 + 字）
2. 图标形状（勾 / 三角 / 圆，形状本身可区分）
3. 文字标签（「安全」「需谨慎」「有数据风险」直接写出来）

### 5.5 症状向导 `/wizard/`

**目的**：给「不会描述问题」的用户一条兜底路径。**7 个问题 + 1 个结果页**（≤8 屏），每步 2–4 个选项，最终输出 1–3 篇推荐教程。

| 步骤 | 问题 | 选项 |
|---|---|---|
| 1 | 你的设备是什么？ | Windows 电脑 / Mac / 手机平板 / 路由器或网络设备 |
| 2 | 现在能开机吗？ | 能正常进系统 / 能开机但进不去桌面 / 完全没反应 |
| 3 | 主要是什么问题？ | 上不了网 / 卡顿死机 / 黑屏蓝屏 / 外设不工作 / 发热异响 / 其他 |
| 4 | 是所有网络都不行，还是只有这台设备？ | 所有设备 / 只有这台 / 不确定 |
| 5 | 是 Wi-Fi 还是网线？ | Wi-Fi / 网线 / 都试过 |
| 6 | 网络图标显示什么？ | 已连接但没网 / 无连接（红叉或叹号） / 找不到 Wi-Fi / 不确定 |
| 7 | 最近装过什么或改过什么？ | 装过代理/VPN/加速器 / 装过杀毒或优化软件 / 改过网络设置 / 都没有 |
| 8 | 结果 | → 推荐 1–3 篇 + 「都不是？去搜索」 |

**交互规格**

- 一次只显示一个问题（移动端友好）；顶部显示进度 `3/7`。
- 支持「上一步」回退，答案保存在 URL hash 里（可分享 `#s=1123`）。
- 每步选择即自动前进，无需「下一步」按钮（减少一次点击）；但保留按钮以便键盘用户。
- 结果页按「最可能解决」排序，每篇附一句「为什么推荐这篇」。
- **全程纯前端**，无后端请求；向导逻辑由一份 JSON 规则表驱动（见 §7）。

## 9. 无障碍、性能与 SEO

### 9.1 无障碍（A11y）

| 项 | 要求 |
|---|---|
| 对比度 | 正文 ≥4.5:1，大字/图形 ≥3:1；**已逐项实测（见 §4.3）** |
| 焦点 | 全部可交互元素 2px 焦点环 + 3px offset；顺序与视觉一致 |
| 语义 | `lang="zh-CN"`、标题层级不跳级、`main`/`article`/`nav`、skip link |
| 搜索 | combobox ARIA 模式；结果数用 `aria-live="polite"` 播报 |
| 步骤 | 用 `<ol>`；勾选按钮 `aria-pressed`；「失败怎么办」用 `<details>` 原生折叠 |
| 命令 | `<pre><code>`；复制按钮有可访问名「复制命令」 |
| 风险 | **不靠颜色单独表意**（颜色 + 图标形状 + 文字标签三重） |
| 触控 | ≥44×44px；不用 hover 作为唯一交互 |
| 动效 | 尊重 `prefers-reduced-motion` |
| 缩放 | 200% 缩放不横向溢出；不禁用用户缩放 |

### 9.2 性能预算

| 指标 | 目标 | 说明 |
|---|---|---|
| LCP | < 2.0s（4G） | 首页 Hero 文本为主，无大图阻塞 |
| CLS | < 0.05 | 所有图片/插画预留尺寸 |
| INP | < 200ms | 搜索为纯本地计算，索引分片加载 |
| 首屏 JS | < 30KB（gzip） | 零框架、零运行时依赖 |
| 首页总重 | < 250KB（不含字体） | 字体走系统回退优先 |
| 搜索响应 | < 50ms | 索引分片按需加载 |

**低配设备策略**：不使用 WebGL、不使用第三方统计脚本、字体优先系统栈（CJK 子集按需）。

### 9.3 SEO

| 项 | 做法 |
|---|---|
| 每篇教程 | 独立 `title` / `description` / `canonical`，标题即用户问题原话 |
| 结构化数据 | `HowTo`（步骤）+ `FAQPage`（常见误判）+ `BreadcrumbList` |

| 首屏内容 | 结论与步骤直接在 HTML 中，不依赖 JS 渲染 |

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **子域无有效 HTTPS 证书**（实测为 IP 自签证书） | 浏览器拦截，站不可用 | **上线前必须签发 Let's Encrypt 证书**；作为 Phase 0 唯一硬性前置 |
| 内容生产工作量被低估 | 站点空壳，无价值 | 先做 20 篇「最高频」教程验证闭环；模板化写作；每篇 15–30 分钟可成稿 |
| 教程写错导致用户数据丢失 | 严重信任与责任问题 | 三级风险标注 + 「有数据风险」操作强制前置备份提示 + 双人复核 + 更新日志留痕 |
| 搜索召回差（中文口语） | 用户搜不到就离开 | 同义词/别名表 + 症状向导兜底 + 零结果查询回收（见搜索方案） |
| 薄荷绿对比度陷阱 | 可读性/无障碍不达标 | §4.3 已定死「只做面不做字」，实现期用脚本复核 |
| 代理/VPN 类内容合规 | 内容风险 | 只讲「企业代理配置与排障」「系统代理导致的故障」，不提供翻墙方法与工具 |
| 移动端用户在坏电脑上查 | 首屏体验决定成败 | 移动优先；搜索框吸顶；结果页零跳转 |
